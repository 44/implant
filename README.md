# IMPLANT

Wrapper around magic-wormhole (and optionally croc) for sending a payload,
then running its `install.py` on the receiving machine.

A payload is a folder containing `install.py` (self-contained script, executed
with `uv`) plus whatever files it needs.

## Backends

Neither backend is a mandatory dependency of `implant` itself. In `croc` mode
no wormhole-related command is built or resolved, so nothing is fetched via
`uvx`.

`--transfer wormhole` (default) uses [magic-wormhole](https://github.com/magic-wormhole/magic-wormhole).
If the `wormhole` binary is missing it falls back to
`uvx --no-config magic-wormhole`; pass `--offline` to disable that fallback and
require an installed backend. You can also ship it in the tool environment:

```bash
uvx --from 'implant[wormhole]' implant
```

`--transfer croc` (or `--croc`) uses [croc](https://github.com/schollz/croc) and
requires `croc` to be installed on both machines. `croc` is a single Go binary,
so there is no Python extra for it.

Auto-detection (`--transfer auto`, default) picks `wormhole`, then `croc`, then
`uvx`-provided wormhole. Use `--wormhole` / `--croc` as shortcuts.
Note: croc only supports the reverse flow, because croc codes are always
generated by the sender. It has no "allocate a code and wait" mode.

## Normal mode (receiver generates the code)

Receiver:

```bash
uvx --from git+https://github.com/44/implant implant
```

This shows a code like `7-abcde-fghij` and waits. Sender then runs:

```bash
uvx --from git+https://github.com/44/implant implant --send /path/to/folder --code 7-abcde-fghij
```

## Reverse mode (sender generates the code)

Sender:

```bash
uvx --from git+https://github.com/44/implant implant --send /path/to/folder
```

The sender prints the code. Receiver then runs (no allocate/wait step):

```bash
uvx --from git+https://github.com/44/implant implant --code 7-abcde-fghij
```

Reverse mode works with both backends, e.g.:

```bash
# sender
implant --croc --send /path/to/folder
# receiver, using the code printed by croc
implant --croc --code 1234-some-croc-code
```

## What the receiver does

The payload is downloaded into a temporary directory, `install.py` is located
(either at the top level or inside the received folder) and executed with
`uv run`.
